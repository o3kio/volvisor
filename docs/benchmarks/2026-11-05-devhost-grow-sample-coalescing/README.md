# Control-plane benchmark evidence — 2026-11-05 per-VG grow capacity-sample coalescing, single-host development lab

This bundle records the clean-tree measurement of option C from the
[grow-tail decision memo](../../reviews/2026-11-05-grow-tail-decision.md):
per-VG single-flight `vgs` capacity sampling for grow admission. It is a
**single-host development-lab** record: one `volvisord` on one host, a
disposable loop-backed LVM volume group, control-plane HTTP only. It is
**not** production evidence, **not** a data-path benchmark, **not** an SLA,
and **not** the issue's 24-hour soak (a shortened 25-minute soak ran).

**Headline: this run measures a c128 regression, not an improvement.**
Aggregate c128 throughput fell **655.326 → 508.225 ops/s (−22.45%)** versus
the `4290b84` bundle. The per-grow tail narrowed (p95 **19,633.371 →
12,396.977 ms**, max **34,044.828 → 15,251.096 ms**), but the grow median
rose (**8,338.505 → 11,335.103 ms**), aggregate write p95 rose
(**5,078.906 → 10,772.171 ms**), and the 25-minute soak fell
**4,756.348 → 4,543.361 ops/s (−4.48%)**. See [REPORT.md](REPORT.md) §6–§9.

## What this run tests

Option C replaced per-attempt `vgs` sampling with one in-flight round per
VG: the first grow admission for a VG runs `vgs`, concurrent grows for that
VG wait for exactly that round and share its success or typed failure, and a
caller arriving after the round clears starts a fresh sample. The allocation
epoch, the reservation check and the durable-first grow intent are
unchanged. The design, tests and adversarial review are recorded in the
[decision memo §9](../../reviews/2026-11-05-grow-tail-decision.md) and the
[diagnostic implementation response](../../reviews/2026-11-05-grow-tail-phase-diagnostic.md).

The intended effect was to remove the c128 `vgs` sample-retry convoy
identified by the non-evidence phase diagnostic and reduce the grow tail
without weakening durability, fencing or idempotency. This run measures what
happened on one host:

- **Aggregate c128 throughput regressed.** 20,732 ops in 40.793 s
  (**508.225 ops/s**) versus 25,816 ops in 39.394 s (**655.326 ops/s**);
  first-30-s window **682.0 vs 851.3 ops/s**.
- **The grow tail narrowed but the median worsened.** Grow p50 **+35.9%**,
  mean **+10.8%**, p95 **−36.9%**, p99 **−55.1%**, max **−55.2%**.
- **The aggregate write p95 rose 112.1%**, but it is a quantile of a
  bimodal mixture and is not like-for-like across SHAs. Both the `4290b84`
  and `75beea3` write p95 values are grow values, at roughly the 14th and
  31st percentile of their respective grow distributions. See
  [REPORT.md](REPORT.md) §6.2.
- **Grow completions barely changed** (**438 → 433**) because the mixed
  driver assigns a fixed number of grows per worker; the throughput loss is
  in the read/attach/report/detach work that did not fit while grows
  occupied workers longer. Grow completion rate was **11.118 → 10.615/s**.
- **The soak also declined slightly** (**−4.48%** ops/s) and its grow p50
  rose **+14.9%**. Micro create/delete were **+5.6% / +7.1%** slower p50,
  consistent with several percent of host/run drift; the c128 throughput
  loss is much larger than that drift.
- **No default-cap errors.** All default-cap sweep requests returned 2xx;
  the diagnostic cap-32 probe recorded **576** `503`s (versus 434) and the
  rate probe recorded the same **959** `429`s.
- **The shortened soak remained healthy.** 6,815,052 ops, 81 client network
  errors at the planned mid-soak restart, 4/4 volumes listed in 0.648 s.
  The 24-hour soak is **NOT RUN**.

## Same-SHA sensitivity (non-evidence)

A single sweep-only repeat at the same SHA and binary (`--skip-soak`) is
recorded in [REPORT.md](REPORT.md) §11.3 to show whether the c128
regression reproduced. It is **not** part of this bundle and is not
evidence; it is cited only so the single published sample is not
cherry-picked. See that section for the measured values and their
limitations.

## What changed in the code

`a07203e` added per-VG single-flight sampling in
`crates/volvisor-lvm/src/provider.rs`: `coalesced_vg_capacity`,
`CapacityRound`, `CapacitySampleState` and `CapacitySampleFlight`. Each call
— sample or wait — consumes one `GROW_ADMISSION_ATTEMPTS` attempt; a waiter
never re-samples internally; a failed round is shared instead of retried per
waiter; a sampling panic publishes a typed failure and clears the slot. The
allocation-epoch protocol and `prepare_grow` reservation check are
unchanged. The workspace tests, `cargo fmt`, workspace clippy and two
independent adversarial reviews (plus a final delta review) passed before
the measurement.

## What it also exposed (open residuals)

These are findings, not fixes, and they are not production claims:

- **The coalescer did not improve the c128 envelope.** Grow completion rate
  is **10.615/s**, at or below the previously accepted **~11–12/s** band;
  aggregate c128 throughput and write p95 are worse than `4290b84`. The
  measured mechanism is a flatter, higher grow distribution (median up,
  tail down), not a faster one.
- **The mechanism is not instrumented in this run.** This bundle has no
  per-grow `vgs` attempt counter, no stale-round count and no admission-loop
  timing. The earlier 783–1,082 stale attempts and 5.0–6.3 s admission loop
  are `4290b84` diagnostic values and must not be projected onto this SHA.
  Plausible causes (cohort synchronization on shared rounds, shared stale
  rounds consuming waiter attempts, `vgs` no longer being the removable
  bottleneck at this composition) remain hypotheses; the data does not
  choose between them.
- **The c128 grow queue remains LVM-bound.** A per-VG resizes serialize on
  the host LVM lock. No provider-side sample change can raise that bound.
- **Shared-cap grow starvation posture.** The daemon admission cap is shared
  with reads and attaches, mutations have no execution timeout, and rate
  limiting is off by default. A sustained grow flood can shed reads/attaches
  with `503`; the cap-32 probe shows this. Documented in
  `docs/admission-control.md`; not solved here.
- **Create still holds the state lock across its `vgs` sample and
  `lvcreate`/`lvs`.** The mixed sweep has no create/delete, so it is not
  measured here.
- **RSS/journal are single-run observations.** The soak RSS peak was
  2,580,376 KiB (versus 2,361,868 KiB) and the journal ended at 54,075,830 B
  (versus 49,560,395 B). A leak is neither proven nor ruled out; the default
  INFO daemon log is unbounded.
- **The 25-minute soak is not the 24-hour soak.** The 24 h soak is **NOT
  RUN**.

## Capacity in one line

At 30 s per tier with the product default admission cap of 256, measured
throughput was **1,813.922 ops/s at 1 in-flight**, **3,837.267 at 8**,
**2,572.763 at 32**, and **508.225 at 128** (completion-inclusive; the first
30 s window completed **682.0 ops/s** at c128). Overall p95 latency was
**1.461 → 7.431 → 45.742 → 154.553 ms**. The 25-minute soak sustained
**4,543.361 ops/s**. This is a measured **regression** relative to
`4290b84`; it is not a throughput improvement, not a validated envelope and
not a fix for the c128 grow queue.
