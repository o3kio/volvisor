## What this run verifies

The run exists to measure the E1+E2 tree with the same 1/8/32/128 sweep and
25-minute soak as the prior runs. **It is a measured mixed-throughput
regression, not a gain:**

- **Mixed throughput fell** at c8/c32/c128: **3,846.899 → 3,756.659 ops/s
  (−2.35%)**, **2,609.257 → 2,476.245 (−5.10%)**, **655.326 → 610.988
  (−6.77%)**; c1 was flat (**1,825.419 → 1,822.948, −0.14%**). Within the
  first 30 s c128 completed **852.3 → 839.0 ops/s (−1.56%)**.
- **The shortened soak fell**: **7,134,530 → 6,626,734 ops** and
  **4,756.348 → 4,417.815 ops/s (−7.12%)**. It recorded 48 network errors
  (46 `ConnectionRefusedError`, 2 `RemoteDisconnected`) at the planned
  restart, no HTTP/provider errors.
- **The c128 tail is lower but not like-for-like.** Overall p95
  **117.870 → 100.558 ms** and read p95 **6.584 → 4.691 ms**; the aggregate
  write p95 **5,078.906 → 4,297.266 ms** lies in the grow population in both
  runs (slowest non-grow write 930.797 ms here, 819.067 ms before), while
  grow p50/p95 **8,338.505/19,633.371 → 10,390.696/22,079.170 ms** got worse.
  The move is a composition shift, not a create/delete improvement.
- **Micro create/delete are neutral/unattributed.** create p50
  **184.771 → 194.991 ms (+5.5%)**, delete p50 **144.307 → 154.492 ms
  (+7.1%) in this single sample. A concurrency-1 create/delete cannot benefit
  from releasing the state lock, and there is no same-SHA repeat.
- **The mixed sweep and soak contain no create/delete calls**, so none of
  their deltas is attributed to E1/E2. The measured change is a lock-scope
  hardening; this run does not claim a throughput gain for it.
- **The lock-scope safety is test-covered, not load-proven.** Deterministic
  gate tests park `lvcreate`/`lvremove` and show another volume's attach
  completing, grow admission honoring the create reservation, and duplicate
  structural mutations refused. Both gates fail on the pre-change provider.
  This harness is a load generator, not a crash-consistency test.
- **Restart replay is healthy.** All `OK`; mid-soak 4/4 volumes in 0.345 s,
  pre-soak 0.081–0.103 s, post-soak 0.283–0.285 s.
- **Provider state stays bounded** at 2,977 B end; the journal ended at
  17,862,039 B (vs 49,560,395 B at the comparator). RSS peak was 2,492,976
  KiB (vs 2,361,868 KiB); a leak is neither proven nor ruled out. The raw
  daemon log has 0 ERROR and 1,446 WARN, all known grow-notification retries
  for attachments without a `vmm_disk_id`.

## What it also exposed (open residuals)

These are findings, not fixes, and they are not production claims:

- **Create/delete still retain short in-lock steps.** Delete's `lvs`
  existence check and create's `pick_pool_vg` `vgs` sample remain inside
  their admission critical sections; the failed-create compensation's
  `lvremove` remains inside the reacquired critical section.
- **The c128 grow queue/tail is unresolved** and LVM-per-VG-bound; this run
  did not improve it.
- **No same-SHA repeat was run**, so the one-run micro/sweep deltas are not
  separated from host/run drift.
- **The 25-minute soak is not the 24-hour soak.** The 24 h soak is **NOT
  RUN**.

## Measured envelope in one line

At 30 s per tier with the product default admission cap of 256, measured
throughput was **1,822.948 ops/s at 1 in-flight**, **3,756.659 at 8**,
**2,476.245 at 32**, and **610.988 at 128** (completion-inclusive; the first
30 s window completed **839.0 ops/s** at c128). Overall p95 latency was
**1.462 → 7.540 → 46.651 → 100.558 ms**. The 25-minute soak sustained
**4,417.815 ops/s**. This is a regression against `4290b84`, not a Phase E
gain.
