write-path lock-scope change at
`2c5b0659a68b5ce6b9286c5c1cd1df7a92f8ebb1` (E1 delete `8cfa4c2`, E2 create

## 1. Scope and what changed

Phase E releases the single provider state mutex across the long external
LVM commands of create and delete, keeping the durable intent as the
fail-closed recovery anchor.

- **E1 (`8cfa4c2`) — delete.** The durable delete intent is saved under the
  state lock, the guard is dropped for `blkdiscard`/`lvremove`, and a fresh
  critical section removes the record, delete intent and stale intents after
  revalidating the volume and the exact intent. A per-volume delete drive
  refuses a duplicate delete.
- **E2 (`2c5b065`) — create.** The durable create intent is saved under the
  state lock; `lvcreate` and its size-verifying `lvs` run without it; the
  final commit reacquires the lock, revalidates the same intent, inserts the
  record, drops the intent and saves once. A create takes the existing
  per-VG capacity reservation under the lock before releasing it and releases
  it (after bumping the allocation epoch) when the command returns. A
  create/delete structural drive map refuses a concurrent structural
  mutation of one volume.

The measured slice changes only create and delete. **The mixed sweep and the
soak contain no create/delete calls**, so any change in their throughput or
latency at this SHA cannot be attributed to E1/E2. This report states that
plainly rather than presenting host/run drift as a Phase E gain.

Recorded E3 residuals, unchanged by this slice: delete's short `lvs`
existence check still runs inside its first critical section; `pick_pool_vg`'s
`vgs` sample still runs inside create admission; the failed-final-save
compensation (`compensate_unpersisted_create`) still runs its checked
`lvremove` inside the reacquired critical section. Separately, create and
delete still run their synchronous LVM bodies inline on async workers (only
grow uses `run_blocking_body`; move's request path runs its CLI calls inline
and only its long supervision loop sleeps asynchronously); with at least as
many concurrent structural bodies as runtime workers, those workers can be
pinned. This is pre-existing and not introduced by E1/E2, but it bounds the
"no longer queues every mutation" statement to in-flight structural bodies
below the worker count. It is recorded in §10.

## 2. Test evidence at the measured SHA

At `2c5b065`, before the run:

- `cargo fmt --all --check` passes.
- `cargo clippy --workspace --all-targets --locked -- -D warnings` passes.
- `cargo test --workspace --locked` passes (`exit=0`), including the LVM
  tests (87 + 16 + 1 + 88 + 52).
- Deterministic gate tests park the fake `lvremove` and `lvcreate`. While
  parked, an attach on a different volume completes, the deleting/creating
  volume is fenced, grow admission honors the create's reservation, and a
  second structural mutation of the same volume is refused.
- Both gate tests were shown to fail on the pre-change provider as negative
  controls. The create negative control times out because another volume's
  attach waits on the state lock (`Elapsed(())`).
- The gate tests exercise a duplicate of the *same* kind (create during
  create, delete during delete). The cross-kind refusal (create during
  delete, delete during create) is implemented by the shared structural
  drive map but is not directly exercised by a gate test; that is a test
  coverage gap, not a known behavioral gap.

These are test evidence, not measurements. This harness does not inject
crashes or kill the daemon during a create/delete.

The candidate's slowest non-grow write is **930.797 ms**, below its
4,297.266 ms write p95; the p95 therefore lies in the grow distribution.
The comparator's slowest non-grow write is **819.067 ms**, below its
5,078.906 ms write p95; its p95 also lies in the grow distribution. The

percentile landed at a different point of a broad grow distribution; the

### 9.1 What this measurement supports

- A fresh, clean-tree measurement at the exact E1+E2 SHA, with the release
  binary digest pinned to that tree.
- The honest E3 verdict: **a mixed-throughput regression** at c8/c32/c128
  (−2.35%/−5.10%/−6.77%) and in the 25-minute soak (−7.12%), with c128 p95

queue improved; a capacity, SLA, durability or data-path claim; or the
24-hour soak.

## 10. Caveats and NOT RUN

- Single host, loop-backed LVM, loopback HTTP, control plane only. Not a
  data-path benchmark, not production capacity, not an SLA, not a
  durability test.
- The 24-hour soak is **NOT RUN**; the run is 25 minutes with one restart.
- No second physical host, real Ceph, DRBD, physical-disk LVM, witness or
  storage-side fencing. Multi-host loss and D3 storage-side fencing are not
  exercised.
- No crash-consistency fault injection in this harness. The create/delete
  lock-scope safety and crash windows are covered by the test suite, not
  this run.
- Single non-fixed-dataset runs; one sample per tier and no same-SHA repeat
  for this bundle. The micro and sweep deltas are one-run observations.
- RSS and journal are single-run observations. RSS peak is 2,492,976 KiB; a
  leak is neither proven nor ruled out. The default INFO daemon log is
  unbounded (2.24 GB / 2.09 GiB raw here), an operational finding.
- The cap-32 and rate-50 probes are diagnostic shapes, not capacity results.
- Recorded residuals: delete's `lvs` check and create's `pick_pool_vg` `vgs`
  sample remain inside their admission critical sections; the failed-create
  compensation's `lvremove` remains inside the reacquired critical section;
  create and delete still run their synchronous LVM bodies inline on async
  workers (only grow uses `run_blocking_body`; move's request path runs its
  CLI calls inline), so sustained concurrency at or above the worker count
  can pin the runtime — pre-existing, not introduced by E1/E2; the
  same-kind gate tests do not directly exercise the cross-kind create-vs-
  delete refusal; the c128 grow queue/tail remains LVM-per-VG-bound and
  unresolved.
- #62 stays open. No gate verdict changes. No production-support, SLA,
  zero-RPO, release or hardware/multi-host claim is made.
