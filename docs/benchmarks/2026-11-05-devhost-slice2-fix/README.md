# Control-plane benchmark evidence — 2026-11-05 D3 slice-2 grow-lock fix, single-host development lab

This bundle records the clean-tree re-measurement of the Phase D D3 slice-2
write path at the fix for the measured high-in-flight write tail. It is a
**single-host development-lab** record: one `volvisord` on one host, a
disposable loop-backed LVM volume group, control-plane HTTP only. It is
**not** production evidence, **not** a data-path benchmark, **not** an SLA,
and **not** the issue's 24-hour soak (a shortened 25-minute soak ran).

- **Exact source:** `8029df8e8f6e1856499927df6f434422894005ad`
  (`volvisord 8029df8`).
- **Worktree at run time:** clean (`worktree_dirty: no` in
  [ENVIRONMENT.txt](ENVIRONMENT.txt), `raw/00-orchestration.log` and every
  raw JSON record).
- **Run window:** 2026-11-05T09:29:39Z .. 2026-11-05T10:00:20Z. The release
  binary was built before the run (`cargo build --release --locked -p
  volvisord`, `CARGO_BUILD_JOBS=4`); `--skip-build` was used so the recorded
  source and the executed binary are the same tree.
- **Host:** one development host (`dev`, Ubuntu 24.04.5 LTS, kernel
  `6.8.0-142-generic`, 16 vCPUs on an AMD EPYC 9554P, 31.3 GiB RAM, QEMU

- **Binary:** release build, SHA256
  `18f260c2ef878985f23fdcc15a659d36db87ff7209477756e98638ff0e28b941`.
- **Environment and absent capabilities:** [ENVIRONMENT.txt](ENVIRONMENT.txt).

## What this run verifies

The run exists to confirm, with the same 1/8/32/128 sweep and 25-minute soak
as the prior runs, that moving the provider state lock out of the `lvextend`
window removes the measured serialization:

- **c32 recovered.** Throughput **858.371 → 1830.005 ops/s** (+113.2 %) and
  write p95 **590.847 → 206.203 ms** (−65.1 %) versus `c4b0b13`. The c32
  write tail is now below the older pre-regression baseline (`aab773b`,
  388.84 ms).
- **c128 improved but is not fully back to baseline.** Throughput
  **237.088 → 440.376 ops/s** (+85.7 %) and write p95
  **6330.548 → 3413.886 ms** (−46.1 %) versus `c4b0b13`; the write p95 is
  still about 2.2× the `aab773b` baseline (1552.261 ms). The harness does
  not attribute the remaining tail.
- **No sweep errors.** All **213,728** default-cap requests returned 2xx at
  every tier, with real grows exercised (4 / 32 / 128 / 255 grow calls at
  c1 / c8 / c32 / c128).
- **c1/c8 throughput fell.** **1729.154 / 3118.787 ops/s** at c1/c8, versus
  **1845.526 / 3410.746** at `c4b0b13`. This is recorded honestly and not
  attributed; it is not presented as a capacity result.
- **Read latency stays low.** Read p95 is **1.481 ms** at c32 and
  **87.276 ms** at c128, versus 179.332 ms / 1288.505 ms at the older
  pre-regression baseline.
- **The shortened soak completed 6,640,950 ops at 4425.586 ops/s** with
  **0 HTTP errors and 0 attachment conflicts**; the 46 network errors are
  client reconnects at the planned restart. The post-fix baseline
  (`aab773b`) ran 5,424,744 ops at 3616.49 ops/s (+22.4 %). RSS delta was
  **+2,126,132 KiB** (peak **2,538,456 KiB**), versus **+2,943,816 KiB**
  (peak 3,236,184 KiB) at `c4b0b13`; this is a single non-fixed-dataset run
  and is **not** a capacity claim.
- **Provider state stays bounded** at **3,147 bytes** end (**3,950 B** max),
  and the journal stays bounded at **75,496,834 bytes** end
  (**75,497,693 B** max, consistent with the documented compaction
  hysteresis).
- **Restart replay is healthy.** The mid-soak restart listed 4/4 volumes in
  **0.264 s** with unchanged state and journal sizes; pre/post-soak restarts
  recovered in 0.082–0.205 s.
- **The generation fence and crash semantics are exercised by the test
  suite** at `8029df8`, not by this harness. This harness is a load
  generator; it is not a crash-consistency test.

## What changed in the code

`grow_volume` no longer holds the provider state mutex across `lvextend` and
size verification. It prepares under the lock (capacity check, in-memory
capacity reservation, durable grow intent), runs the resize with the lock
released, and commits by reacquiring the lock and re-validating the exact
intent and volume generation. The durable intent remains the recovery
anchor; fresh attach, detach, delete, move start and move completion are
refused typed while it is live, while reports stay admitted. A per-VG
in-memory reservation preserves capacity atomicity for creates and other
grows, and the move reconcile pass defers only the record whose volume is
growing instead of aborting the pass.

## What it also exposed (open residuals)

These are findings, not fixes, and they are not production claims:

- **Residual c128 write tail.** Write p95 at c128 is 3413.886 ms, down 46.1 %
  from the regression run but still above the older baseline. The harness
  does not attribute the remainder (grow intent fsyncs, the synchronous
  writer funnel, or the harness mix are candidates, not findings).
- **c1/c8 throughput drift.** Both tiers measured below both prior clean
  runs. No cause is claimed.
- **RSS high-water is improved but still above the older baseline.** Peak
  2,538,456 KiB versus 3,236,184 KiB at `c4b0b13` and 2,323,028 KiB at
  `aab773b`. A leak is neither proven nor ruled out.
- **The default INFO daemon log is unbounded.** The ~30-minute run produced
  2,223,082,241 bytes (≈2.07 GiB) and 8,263,668 lines (8,263,085 INFO,
  583 WARN, 0 ERROR) with no rotation. The committed copy is
  `raw/daemon.daemon.log.gz` (58,555,280 bytes compressed). Logging volume is
  an operational finding, not a durable-state defect.
- **The cap-32 admission probe shed load.** 16 requests returned `503` under
  the probe's configured 1 s queue timeout. The default-cap sweep had
  0 `503`/`429`. The probe is diagnostic and is not a capacity result.
- **The 25-minute soak is not the 24-hour soak.** The 24 h soak is **NOT
  RUN**.

## Capacity in one line

At 30 s per tier with the product default admission cap of 256, measured
throughput was **1729.154 ops/s at 1 in-flight**, **3118.787 ops/s at 8**,
**1830.005 ops/s at 32**, and **440.376 ops/s at 128**; overall p95 latency
was **1.542 ms → 9.125 ms → 88.969 ms → 1836.718 ms** respectively. The
25-minute soak sustained **4425.586 ops/s**. This is a measured recovery of
the c32/c128 grow-lock serialization, not a blanket throughput claim; see
[REPORT.md](REPORT.md) §5–§10 and §11 for the split latencies, the residual
c128 tail, and the caveats.

## What this bundle is not

- **Not production evidence** and not a support-matrix change.
- **Not multi-host.** There is no second physical host, no real Ceph, no
  DRBD, no physical-disk LVM, and no independent failure domain.
- **Not a data-path benchmark.** No guest I/O, no block-data proxying, no
  filesystem or fio workload, no disk IOPS/latency.
- **Not the 24-hour soak.** The shortened soak ran for 25.0 minutes, with one
  mid-run restart.
- **Not an SLA or capacity plan.** All numbers are one host, one loop-backed
  VG, one process. The loop image and the journal/state files share the same
  ext4 filesystem.
- **Not a durability proof.** It exercises acknowledged control-plane writes;
  it does not prove crash consistency or data-path durability.
- **Not a full write-tail fix.** c32 is back below the pre-regression
  baseline; c128 is much improved but still above it.

## Reproduction

```bash
# Build the release binary first (REPORT.md §4), then use a fresh run dir.
sudo scripts/bench/run-all.sh \
  --run-dir /tmp/opencode/volvisor-bench-$(date -u +%Y%m%dT%H%M%SZ) \
  --skip-build --sweep-seconds 30 --soak-minutes 25
```

Use a **fresh** run directory: `run-all.sh` appends to an existing run's logs
and does not clean its journal/state. The recorded run used
`/tmp/opencode/volvisor-bench-fix-8029df8-20261105T092939Z`; that workspace
copy is now populated and must not be reused verbatim. The committed bundle
is the durable evidence copy. Verify the bundle with
`sha256sum -c MANIFEST.sha256`. Re-generate the comparison with:

```bash
python3 scripts/bench/compare.py \
  --before docs/benchmarks/2026-11-04-devhost-slice2 \
  --after docs/benchmarks/2026-11-05-devhost-slice2-fix \
  --out /tmp/opencode/slice2-fix-compare
```
