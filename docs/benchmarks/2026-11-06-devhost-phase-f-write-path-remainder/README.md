## What this run verifies

The run exists to measure the `2edcecd` tree with the same 1/8/32/128 sweep
and shortened 25-minute soak as the prior runs, and to confirm the build and
test evidence at that SHA. The timed sweep and soak contain **no
create/delete/move calls**; Phase F's production changes are confined to
create/delete (F1 adds move regression tests only), so no sweep or soak
delta is attributed to Phase F. No throughput or zero-regression claim is
made.

- **Test evidence.** `cargo fmt --all --check` exit 0; `cargo clippy
  --workspace --all-targets --locked -- -D warnings` exit 0; `cargo test
  --workspace` exit 0 with 78 `test result:` lines, 1,378 passed, 0 failed,
  3 ignored (65 test binaries + 13 doc-test binaries). All seven Phase F
  gate tests pass individually. The ten #63 schema/filter/fence tests and
  the listed #64 retention/compaction/tombstone/config tests pass. These
  are deterministic test evidence, not crash injection.
- **Micro create/delete differences are descriptive only.** create p50
  **195.561 → 205.42 ms (+5.04%)**, p95 **215.488 → 225.682 ms (+4.73%)**;
  delete p50 **154.685 → 174.612 ms (+12.88%)**, p95
  **174.961 → 185.304 ms (+5.91%)** versus the prior `7204a53` bundle. A
  same-SHA non-evidence repeat measured create p50/p95 215.203/235.718 ms
  and delete 174.623/194.684 ms. No A/B at `7204a53` was run in this batch,
  so this is not attributed to Phase F and is neither a regression nor a
  gain.
- **The sweep is mixed and c128 fell in this sample.** c1 **1,837.885 →
  1,826.312 ops/s (−0.63%)**, c8 **3,824.485 → 3,743.924 (−2.11%)**, c32
  **2,436.350 → 2,311.046 (−5.14%)**, c128 **462.899 → 419.873
  (−9.29%)**. Measured p95 was 1.451 / 7.401 / 45.273 / 138.175 ms; p99
  was 1.56 / 11.478 / 93.864 / 11,800.496 ms. c128 completed 18,233 ops in
  43.425 s against a nominal 30 s tier (non-evidence repeat: 42.676 s, p99
  12,523.519 ms). **No sweep delta is attributed**; the tier is a
  single-sample, variance-dominated observation. No gain and no
  zero-regression claim is made.
- **The shortened soak completed 7,040,538 operations.** 1,500.003 s, 4
  workers, **4,693.683 ops/s** (success 4,693.645), error rate **8e-06**
  (58 `NETWORK_ERROR`: 55 `ConnectionRefusedError`, 3 `RemoteDisconnected`,
  consistent with the planned restart), p50/p95/p99 **0.304 / 2.864 /
  3.606 ms**. The
  prior `7204a53` run did 7,112,020 ops at 4,741.343 ops/s (−1.005%
  derived). The soak contains no create/delete; the difference is **not
  attributed**.
- **Restart replay is healthy.** All `OK`; pre-soak 0.102–0.103 s (3
  rounds), mid-soak **0.425 s with 4/4 volumes and none missing**,
  post-soak 0.366/0.364 s with 0 volumes listed after soak cleanup.
- **Daemon log:** 0 `ERROR`; 1,553 `WARN`, all the known grow-notification
  retry for attachments without a `vmm_disk_id`.
- **#63 and #64 are code-present, not closed.** The schema-v3 filter is
  decode-only and the strictly increasing attachment generation is the
  fence; the journal has bounded retention, an exact tombstone ring,
  bounded replay eviction, compaction backoff and config wiring. The
  residuals in [REPORT.md](REPORT.md) — including the per-volume-lifetime
  generation-1 reset across delete + same-id recreate, the unbounded legacy
  wire vector at decode, the preserved-but-unused legacy filter, and the
  count-window (not TTL) tombstone expiry — remain open. ADR-0012 is
  **Accepted** (2026-11-06, zoorpha); `#63` remains open.

## What it exposed (open residuals)

These are findings, not fixes, and they are not production claims:

- **The RSS high-water residual (#64) remains.** RSS rose 75,716 →
  2,668,132 KiB with a 2,762,300 KiB high-water (prior 2,842,396 KiB); last
  RSS rose 27.76% (derived) while high-water fell 2.82% (derived). A leak
  is neither proven nor ruled out by one 25-minute sample.
- **The journal high-water sits above the 64 MiB trigger.**
  75,497,904 B versus the 67,108,864 B trigger, essentially identical to
  the prior 75,497,758 B. This is consistent with the documented
  post-compaction growth floor (the code permits a threshold at or below
  the compacted snapshot's own size), not a new unbounded-log finding and
  not a hard-cap claim; the exact peak composition is not separately
  instrumented.
- **The c128 tier is variance-dominated and did not fully drain in 30 s.**
  Its p99 of 11,800.496 ms and 43.425 s duration are reported, not hidden;
  the non-evidence repeat measured p99 12,523.519 ms and 42.676 s.
- **Three implementation residuals are accepted** rather than restructured:
  the failure-only durable re-read in `persist_copying_record` stays under
  the lock, startup `apply_delete_intents` runs the delete CLI under the
  startup lock, and move's CLI calls remain inline on async workers.
- **The 25-minute soak is not the 24-hour soak.** The 24 h soak is **NOT
  RUN**.

## Measured envelope in one line

At 30 s per tier with the product default admission cap of 256, measured
throughput was **1,826.312 ops/s at 1 in-flight**, **3,743.924 at 8**,
**2,311.046 at 32**, and **419.873 at 128** (completion-inclusive). Overall
p95 latency was **1.451 → 7.401 → 45.273 → 138.175 ms**. The shortened
25-minute soak sustained **4,693.683 ops/s**. The c128 sample had a p99 of
11,800.496 ms and did not complete within its nominal 30 s tier; it is not
a property of the change and supports no throughput claim.
