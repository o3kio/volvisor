Lab topology
------------
- Part A: journal directory on a dedicated 256 KiB tmpfs
  ($RUN/lab-d5/journalfs); fake provider; no LVM.
- Part B: loop-backed volume group vg-d5lvm on /dev/loop0; provider state on
  a second 256 KiB tmpfs ($RUN/lab-d5/statefs); journal on ordinary storage
  ($RUN/lab-d5/lvm-journal), so only the state save hits ENOSPC after
  lvcreate.
- The lab creates disposable loop devices, volume groups and tmpfs mounts and
  tears them down. Do not run it on a host with production volume groups.

Raw log retention
-----------------
The harness opens each daemon log with `>`, so a restart truncates it. Before
each restart the drill copies the current incarnation to
raw/d5-daemon.pre-restart.log and raw/d5-lvm-daemon.pre-restart.log. The
current-incarnation logs (raw/*.daemon.log) hold the post-restart activity,
including the terminal replay.

The LVM journal at journal/d5-lvm-journal.log was not snapshotted by the
drill itself. The orchestrator copied it out of the run directory's
lab-d5/lvm-journal/journal.log after the drill had finished and the daemons
were stopped, during the same post-run capture as raw/post-run-cleanup.txt.
It is the raw journal bytes, bound by MANIFEST.sha256; there is no in-log
`cp` line for it, so this is an out-of-band capture disclosed here for the
same reason BINARIES.txt discloses its own out-of-band digests.
