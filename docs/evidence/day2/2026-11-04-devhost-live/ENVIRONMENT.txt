Lab construction
----------------
- D1 and D2 live use a loop-backed LVM VG on a sparse file. The LVM provider
  skips loop devices during discovery, so the harness seeds an
  operator-provisioned device claim (`role: native_pool`) pointing at the loop
  device. This is a lab scaffold, not a production claim procedure.
- D2 uses loop LVM plus the repository's golden schema fixtures, with the
  fixture `vg_name` rewritten to the lab VG so the restored volume can be
  served as Attached rather than Failed.
- D2 live uses separate config files for OLD and NEW; the config fields used
  (listen, journal_dir, provider, lvm_vg_prefix, device_claim_token,
  lvm_state_path, admin_token) are accepted by both commits.
- The D2 live pre-upgrade backup is a tar of the whole stopped journal
  directory (v2 lvm-state.json, v1 journal.log and journal.lock), not a
  single-file copy. The post-upgrade journal is retained at
  records/d2live-journal-post-upgrade.log.
