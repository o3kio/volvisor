## Two release decisions

Volvisor has two distinct decisions. Do not conflate them.

### A. v0.1.0 distribution tag

The **recorded decision** is that the distribution tag may be cut before the
three-physical-host campaigns (#37/#38), provided the
[support matrix](../../SUPPORT_MATRIX.md) and
[release notes](v0.1.0.md) explicitly mark those scenarios **not-run** and
claim nothing beyond the recorded evidence. This is a distribution and
evaluation milestone, not a pre-production or production-support statement.

Its current blockers are:

- the absence of a configured signing key on this host; and
- any code gate that this release actually claims. Every provider marked
  `supported` in [`release-scope.toml`](../../release-scope.toml) must run
  and pass its suite in the release workflow. Today only `native-local` is
  `supported` (LVM suite); `ceph-rbd` and `nearline-replicated` are
  `not-run` and explicitly not claimed.

#40 has landed. Its capture is **same-host** netns/veth (non-loopback
addresses on one kernel), not a second physical host or a cross-host
witness/peer hop; the legacy `admin_token`-only mode still leaves reads open.
Those limits are recorded, not omitted. The CHV pin (#48) waits for a tagged
release and is not claimed here.

### B. Pre-production exit gate (milestone [#36](https://github.com/o3kio/volvisor/issues/36))

This gate is **not** satisfied by a distribution tag. It still requires the
real runs for #37/#38/#39 where claimed, cross-host transport validation
beyond #40's same-host capture, #46, #48, and the exit review. Do not use the
v0.1.0 distribution tag as evidence that pre-production is ready.

**Smoke note.** `packaging/smoke.sh` expects the built package in the current
directory and the repository's `packaging/smoke.sh` available to the
container. The commands above bind-mount the repo's `packaging/` directory
read-only; the release workflow instead runs
`sh ../packaging/smoke.sh "$DESCRIBE" "$VERSION"` from the artifact
directory. Both shapes exercise the same script. The host network was
required only because this container runtime could not resolve distribution
repositories through its default network; it does not change what the smoke
asserts.

**Stamp note.** The `volvisord` version test compares the compiled-in stamp
with a live `git describe`. Rebuild after any working-tree change before
running the full suite: a docs edit alone makes the tree dirty and makes the
old compiled stamp stale, which is a test-harness observation, not a source
failure. The run above was taken at a clean `620b8f7` after a fresh build.
