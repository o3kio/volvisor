> **Volvisor v0.1.0 is not production-supported.** This release, when it is
> cut, is a distribution and evaluation milestone, not a production-support
> statement. There is no SLA, durability guarantee, zero-RPO failover claim,
> or live-migration guarantee. Nothing in these notes may be read as
> readiness for production service.

These notes are a draft for review. The tag is currently **blocked**; the
exact gates and their status are in the
[checklist](v0.1.0-checklist.md). No GitHub release exists.

## What v0.1.0 is intended to contain

The workspace at this release contains:

- the stable volume identity, device-claiming, journal, and idempotency
  control plane;
- the `native-local` LVM provider slice, including grow and same-VG
  relocation;
- the `ceph-rbd` adapter for an **existing, externally operated** Ceph
  cluster (not a managed-OSD implementation);
- the `nearline-replicated` DRBD 9 prototype (host-kernel local end),
  witness/lease fencing, and the DRBD-only migration/handoff surface;
- the experimental Rook-cell device-lending/reclaim surface and design
  inputs — **design and daemon tests only; the POC has never been run**;
- `volvisord` and `volvisor-witnessd`, their systemd units, annotated
  example configurations, `--version`/`--check-config`, and deb/rpm
  packaging metadata.

The crate layout and build instructions are in the
[README](../../README.md) and [START_HERE](../../docs/START_HERE.md).

## Evidence that is pending or blocked

- **Nearline three-physical-host campaign** — [#37](https://github.com/o3kio/volvisor/issues/37)
  is **not run**. There is no evidence for real DRBD, real media flush/FUA,
  power loss, SSD loss, split-brain, peer rejoin, or a 24 h soak across
  physical failure domains. The only nearline VMM evidence is single-host
  Tier V with simulated storage.
- **Rook-cell POC** — [#38](https://github.com/o3kio/volvisor/issues/38) has
  **never been executed and there is no GO**. ADR-0008 remains production
  NO-GO.
- **Ceph/DRBD release gating** — [#39](https://github.com/o3kio/volvisor/issues/39)
  is **not done**. The suites exist but are not required by the release
  workflow; a release can currently pass without them.
- **Transport and authentication** — [#40](https://github.com/o3kio/volvisor/issues/40)
  is **not done**. Non-loopback plain HTTP and a shared admin token remain
  unsuitable for a multi-host pilot.
- **CHV consumer path and pin** — [#48](https://github.com/o3kio/volvisor/issues/48)
  is **not done**. CHV reports at most `advertised`; `active` must never be
  claimed without guest evidence.

## CHV pin decision

**Do not move the CHV pin yet.** The recorded decision is:

1. CHV continues to pin its current Volvisor revision. That revision
   predates the attachment-state capability, so CHV must not claim more
   than its pin supports.
2. Pin CHV to a tagged Volvisor build **only after both**:
   - a tagged Volvisor release exists (this v0.1.0 release, after its
     pre-tag gates pass), and
   - [#48](https://github.com/o3kio/volvisor/issues/48) has landed the CHV
     consumer path, capability negotiation, integration test, and published
     version matrix.
3. The pin update is a **conscious change in the CHV repository** with the
   exact supported pair and pin commit recorded there. This repository does
   not edit the CHV repo.
4. CHV's ceiling is `advertised`; `active`/`guest_confirmed` needs a
   separate accepted design and must not be faked.

This is a decision to wait, not a claim that the integration is ready.

## Artifacts (planned)

The release workflow (`.github/workflows/release.yaml`, owned by #39) is
designed to produce, for the exact tagged commit:

- `volvisor_<version>_amd64.deb` — Debian/Ubuntu package;
- `volvisor-<version>-1.x86_64.rpm` — EL/Fedora package;
- `volvisor-<version>-x86_64-unknown-linux-gnu.tar.gz` — both binaries;
- `SHA256SUMS` — checksums over the artifacts;
- `BUILD_INFO.txt` — exact toolchain and build environment.

Both packages carry `volvisord` and `volvisor-witnessd`, their systemd
units, and annotated example configurations at `/etc/volvisor/`. Nothing is
enabled or started automatically. `lvm2` is a hard dependency; `drbd-utils`
(>= 9) is recommended; `ceph-common` is optional. The DRBD 9 kernel module
is a separate host property, not something the package can install.

No artifact list above is a publication claim: **no artifacts exist for a
`v0.1.0` tag until the tag is created and the workflow runs.**

## Install and verify (after a future, gated release)

These are the commands the release pipeline is designed to verify; they are
not a substitute for reading the packaging notes and the checklist:

```sh
# Debian/Ubuntu
sudo apt-get install ./volvisor_<version>_amd64.deb

# EL/Fedora
sudo dnf install ./volvisor-<version>-1.x86_64.rpm

volvisord --version
volvisor-witnessd --version
volvisord --config /etc/volvisor/volvisor.toml --check-config
volvisor-witnessd --config /etc/volvisor/witnessd.toml --check-config
```

The packaged container smoke verifies installation with dependency
resolution, both version stamps, `--check-config` on the shipped examples,
the file layout, and `systemd-analyze verify` of the units. It does **not**
verify unit start (the smoke containers do not run systemd as PID 1),
upgrade/downgrade transitions, or any architecture other than x86_64.

## Known limitations and safety notes

- Do not use this release with production data or as a production storage
  service.
- Do not point it at a production Ceph cluster or LVM volume group.
- Keep the API on loopback until #40 is done.
- Nearline async replication can lose the newest acknowledged tail on host
  loss; a witness is authority, not data replication.
- No local mirror is implemented; the experiment is declined
  ([ADR-0011](https://github.com/o3kio/volvisor/blob/main/docs/adr/0011-local-mirror-experiment-decline.md)).
- A Tier S or Tier V result is not a Tier R result. Read the
  [support matrix](../../SUPPORT_MATRIX.md) before making any claim.

## Release decision

**Do not tag or publish.** The tag is blocked on the gates listed in the
[checklist](v0.1.0-checklist.md): #37, #38, #39, #40, #48, and a configured
signing key. The pre-production exit gate requires the P0 evidence issues;
this draft deliberately records that state rather than around it.
